# 開放式回答標註手冊（Codebook）

適用於 `tests/fixtures.json` 的 15 組標註，以及任何後續新增的案例。

---

## 0. 這份文件是什麼

**是**：一套把文字轉成四個標籤的規則。標註者照這份規則做判斷。

**不是**：標準答案。這四個構念沒有客觀存在的「正確值」——它們由這份手冊定義。因此輸出的統計量叫**一致率**（agreement），不叫準確率（accuracy）。

這件事的實務意義：如果你照手冊判定 F01 是 `mid`，而引擎輸出 `high`，那是**引擎與手冊不一致**，不是你判斷錯誤。手冊的擁有者是系統設計者，不是模型。

**先寫規則、再標註、標完凍結、最後才看引擎輸出。** 順序顛倒的話，一致率就是自我實現的假數字。

---

## 1. 標註流程

1. 讀完這份手冊。
2. 不要執行 `npm run agreement`，不要看任何引擎輸出。標註必須在未見結果的狀態下完成。
3. 逐組填 `tests/fixtures.json` 的 `expected` 四個欄位。拿不準填 `null`（該欄不計入分母，不會被當成錯）。
4. `git commit` 鎖住。
5. 之後才跑一致率。

### 標完之後發現與引擎不一致

分兩種，處理方式不同：

- **可以做**：發現手冊本身規則不清（例如「論據深度多少算夠」沒定義），→ 修手冊、**15 組全部重標**、在報告寫明經過一輪手冊修訂。這是內容分析的正常程序。
- **不可以做**：單獨把某一組改成引擎的答案。挑著改會讓整份統計失效。

改規則要付「全部重來」的代價，所以不會有人為了一題去改——這就是這條程序的設計目的。

### 建議：第二位標註者

找一位同學獨立標同樣 15 組，計算 Cohen's κ。

- κ 高 → 標註反映的是規則，不是個人偏好
- κ 低 → **規則寫得不夠清楚**，這本身是值得報告的發現

單一標註者不是錯，但要在報告中揭露為限制。

---

## 2. 四個標註欄位

只標這四欄。情緒指標（anxiety / loss_aversion / confidence）在本系統中**只做顯示、不進計分**，因此不在標註範圍內——理由是「如果崩盤我會很恐慌」屬於條件推演，不是當下情緒，會污染文字情緒訊號。

---

### 2.1 `overconfidence`（過度自信）

**定義：語氣強度與論據強度的落差。**

```
過度自信 = 立場強度 × (100 − 論據深度) / 100
```

**與看多看空無關。**「絕對是詐騙」與「絕對會漲」的立場強度完全相同。要判斷的是「話講得多滿」對比「憑據給了多少」。

#### 立場強度只計「關於自己」與「關於將要發生什麼」的宣稱

> **修訂（v1.1）。** 這一小節是定義的修訂，不是澄清。修訂前，任何肯定語氣都計入立場強度。

過度自信在行為財務學裡指的是對**自己**的誤校準——高估自己的能力、高估自己的相對排名、高估自己預測的精確度（Moore & Healy 的三種 overconfidence）。它不是「對世界的事情講得很肯定」。

因此肯定語氣要看它**附著在什麼上面**：

| 句子 | 計入立場強度 | 為什麼 |
|---|---|---|
| 我一定能挑到會漲的那幾檔 | **是** | 關於自己的能力 |
| 我很確定自己看得準 | **是** | 關於自己判斷的精確度 |
| 比特幣絕對會漲到 50 萬鎂 | **是** | 過度精確的預測 |
| 大盤長期向上 | **否** | 關於世界的一般性陳述，而且普遍被接受 |
| 股票長期報酬高於現金 | **否** | 同上 |

**說對一件事，不該被判定為傲慢。** 修訂前的版本會把「大盤長期向上」判成過度自信，受測者的反駁是「但大盤確實長期向上啊」，而他是對的。

這個收緊會讓偽陰性變多（「這檔一定是好公司」這類句子不再計入）。這是刻意的取捨：適合度工具冤枉人一次，受測者就不信任整份報告了；漏判一個邊界案例，沒有人會受害。

#### 兩步驟判斷

**第一步，評立場強度**（只評上表「計入」的那些宣稱）

| 強度 | 語言特徵 |
|---|---|
| 強 | 絕對／一定／保證／不可能／穩賺／必然；全押、全部投入 |
| 中 | 應該會／我認為／看好；比例明確但語氣肯定 |
| 弱 | 可能／也許／不確定／看情況／沒有特別看法 |

程度副詞會調整：「極度／非常／超級」加強，「有點／稍微／還好」減弱。

**第二步，評論據深度**

計入論據深度的內容：
- 價值來源、現金流、供需、稀缺性、成本結構
- 財務數字：營收、毛利率、本益比、費用率
- 總經因素：利率、通膨、匯率
- 明確的持有理由與配置邏輯（角色、相關性、比例依據）

**不**計入論據深度：
- 漲跌幅、倍數、目標價（價格型數字）
- 「是未來」「是趨勢」這類標籤式斷言
- 他人說法（那屬於 `authority`，不是論據深度）
- **被否定掉的機制詞**。「不需要分散」提到分散是為了推翻它，那不是他給的理由（v1.1 修訂）

> 關鍵反例：「絕對會漲到 50 萬鎂，我朋友去年翻三倍」有兩個數字，但**論據深度仍然很低**——兩個都是價格型。

#### 三個等級

| 等級 | 判準 |
|---|---|
| `high` | 立場強烈，且幾乎給不出機制型論據 |
| `mid` | 立場強但有部分論據；或立場中等且論據薄弱 |
| `low` | 立場與論據相稱。**論據充分時，語氣強烈仍然是 `low`** |

最後一列是最常被弄錯的地方：一個人說「我非常確定，因為 A、B、C」，如果 A、B、C 確實是機制型論據，那不是過度自信。

### 2.2 `herding`（從眾）

**定義：以他人的行為或說法，作為自己決策的理由。**

#### 三個等級

| 等級 | 判準 |
|---|---|
| `high` | 他人動向是主要甚至唯一理由（「大家都在買，所以我也買」「如果大家都在賣，我可能也會賣」） |
| `mid` | 他人是觸發點，但仍有自己的考量；或明確表達「怕落後」但同時給了其他理由 |
| `low` | 沒有提到他人；或提到他人但**明確表示不受影響／得出相反結論** |

#### 最容易誤判的地方

**提到別人 ≠ 從眾。** 判斷的是「別人的行為有沒有成為理由」。

- 「朋友都說會漲，但我覺得不合理」→ 出現社會歸因詞，但結論與他人相反 → `low`
- 「我不太會因為別人買就跟著買」→ 明確否定 → `low`
- 「我朋友翻了三倍，所以我也想買」→ `high`

---

### 2.3 `reasoning_mode`（推理模式）

四選一。**取主導的那一個**，不是出現過的都算。

| 值 | 判準 |
|---|---|
| `mechanism` | 從價值來源、基本面、財務數字、總經因素推論 |
| `narrative` | 整體印象、故事、標籤式斷言（「AI 是未來」），缺乏具體依據 |
| `authority` | 主要依據朋友、群組、媒體、分析師、法人、KOL 的說法 |
| `price_action` | 主要依據漲跌幅、倍數、目標價、「跌下來就是買點」 |

#### 混合時怎麼取

問一句：**把這一類理由拿掉，他的結論還站得住嗎？**

- 「輝達營收成長快（機制），而且法人也一直買（權威）」→ 拿掉法人仍然成立 → `mechanism`
- 「分析師說目標價還有空間，所以我有信心」→ 拿掉分析師就什麼都不剩 → `authority`

Q13 與 Q14 若不同，以 **Q13** 為準（Q13 才是他對標的的看法）。

---

### 2.4 `belief_rigidity`（信念僵固）

**必須對照 Q13 的立場來讀 Q14。** 單看 Q14 的「會／不會改變」無法判斷。

| Q13 立場 | Q14 反應 | 判定 | 理由 |
|---|---|---|---|
| 強烈 | 完全不重新評估 | `high` | 新資訊進不去 |
| 強烈 | 會重新檢視假設 | `low` | 立場強但保有認知韌性 |
| 溫和 | 不變（本來就預期波動） | `low` | 沒有需要改變的東西 |
| 溫和 | 因為價格下跌就翻轉看法 | `low` | 僵固度低，但**價格錨定高** |

#### 判斷要點

「不會改變」本身不是僵固。要問的是：**他有沒有說出什麼條件會讓他改變？**

- 「不會改變，跌 40% 正好加碼」→ 沒有任何可推翻條件 → `high`
- 「不會改變，真正會讓我改變的是採用率長期停滯」→ 說得出可推翻條件 → `low`
- 「會重新檢視，如果是監管造成的就減碼」→ 條件式重估 → `low`

`mid` 用在：表示會考慮但說不清條件，或只願意小幅調整比例。

## 3. 訓練範例

以下四例**不在 15 組標註集內**，只用來示範規則怎麼套。

---

**T1** — Q13：「我非常確定台積電會繼續領先，先進製程的資本支出門檻已經高到對手三年內追不上，客戶轉換成本也很高。我會放 20%。」
Q14：「會看是什麼原因。如果是先進製程良率被追上，那我的前提就錯了，會減碼。」

| 欄位 | 判定 | 理由 |
|---|---|---|
| overconfidence | `low` | 語氣很強（「非常確定」），但論據是進入門檻與轉換成本，都是機制型。**強語氣＋強論據＝不是過度自信** |
| herding | `low` | 沒有提到他人 |
| reasoning_mode | `mechanism` | 資本支出門檻、轉換成本 |
| belief_rigidity | `low` | 說得出可推翻條件（良率被追上） |

---

**T2** — Q13：「黃金我覺得還好耶，不太確定，大概就那樣吧，可能放一點點。」
Q14：「不知道，跌了再說。」

| 欄位 | 判定 | 理由 |
|---|---|---|
| overconfidence | `low` | 立場弱，論據也弱，但落差不大 |
| herding | `low` | 沒提到他人 |
| reasoning_mode | `narrative` | 整體印象，沒有具體依據 |
| belief_rigidity | `low` | 本來就沒有強立場可以僵固 |

> 注意：`overconfidence` 低**不代表**這是個好的回答。這兩欄衡量的是不同的事。

---

**T3** — Q13：「同事都在買 00940，我看群組每天在討論。不過我自己算過內扣費用比較高，所以我買別的。」
Q14：「不會改變，費用率的差距跟短期漲跌沒有關係。」

| 欄位 | 判定 | 理由 |
|---|---|---|
| overconfidence | `low` | 立場中等，有具體論據（費用率） |
| herding | `low` | **社會歸因詞出現了，但結論與他人相反**——別人的行為沒有成為理由 |
| reasoning_mode | `mechanism` | 費用率是成本結構 |
| belief_rigidity | `low` | 溫和立場，且理由與價格無關 |

---

**T4** — Q13：「比特幣去年從 3 萬漲到 10 萬，翻了三倍多，這種動能不會突然停。我全押。」
Q14：「不會改變，跌 40% 也是正常回檔，漲回來只是時間問題。」

| 欄位 | 判定 | 理由 |
|---|---|---|
| overconfidence | `high` | 立場極強（全押、「不會突然停」），數字有三個但**全是價格型**，論據深度仍然是零 |
| herding | `low` | 沒有提到他人 |
| reasoning_mode | `price_action` | 完全依據漲跌幅 |
| belief_rigidity | `high` | 沒有任何可推翻條件 |

T4 是 `overconfidence` 判準的核心案例：**有數字不等於有論據**。

## 4. 填寫格式

`tests/fixtures.json` 每組的 `expected`：

```json
"expected": {
  "overconfidence": "high",
  "herding": "low",
  "reasoning_mode": "price_action",
  "belief_rigidity": "high"
}
```

- `overconfidence` / `herding` / `belief_rigidity`：`"low"` `"mid"` `"high"`
- `reasoning_mode`：`"mechanism"` `"narrative"` `"authority"` `"price_action"`
- 拿不準：填 `null`
- `note` 欄可自由寫判斷理由，建議在拿不準或判斷有掙扎時寫下來——這些就是手冊需要補強的地方
