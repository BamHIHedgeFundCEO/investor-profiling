# Digital Investor Profiling System

理財機器人課程作業。使用者填寫問卷後，系統產生三層的動態投資人畫像：Baseline Risk（長期承受度）、Current Emotional State（當下情緒）、Behavioral Alert（行為提醒），並輸出 `target_vol` 供下週的資產配置模組使用。

> 目前進度：**階段 F**（計分引擎、問卷 UI、結果頁、規則式與 Gemini 文字分析、雙情境對照、稽核面板、展示模式；尚未部署）

## 開發

```bash
npm install
npm run dev
npm test          # vitest（含型別測試）
npm run typecheck
npm run agreement            # 規則式與人工標註的一致率
npm run agreement -- --gemini        # 另外跑 Gemini（需 GEMINI_API_KEY）
npm run agreement -- --consistency   # 同一段文字跑 5 次，報告標準差
npm run demo                 # 印出雙情境對照表，並檢查慢變數是否真的沒動
npm run sensitivity          # 敏感度分析（三組分開報，(c) 逐一擾動）
```

環境變數見 `.env.example`。`GEMINI_API_KEY` 只放在伺服器端（本機放 `.env.local`，線上放 Vercel Environment Variables），不會進入前端程式碼。前端用 `VITE_ANALYZER` 決定用哪個分析器，切換不需要改 code。

## 方法學

以下章節隨實作進度累積。

### 1. 三維取最小值，不取平均

`baseline_risk = min(capacity, willingness, competence_cap)`

緊急預備金為零卻宣稱敢賠 50% 的人，系統必須以保守的一方為準。取平均會把矛盾洗成中等分數，而那正是最該被標記的客戶（KYC / MiFID II 的核心邏輯）。

本系統採 capacity / willingness / competence 三維取最小值。知識與經驗不併入風險偏好，而是作為上限（competence cap = 55 + 0.45 × competence），對應 MiFID II 中 appropriateness 與 suitability 的區分。此設計使缺乏市場經驗的受測者上限為 55–77，落在穩健型區間，而非被判定為保守型——缺乏經驗限制的是可承擔的複雜度上限，不是風險偏好本身。

經驗限制是可逆的：它會隨實際經歷市場週期或補足知識而放寬，與財務限制性質不同。

### 2. 情緒只能下調

`emotion_mult ∈ [0.85, 1.0]`。今天很興奮不代表財務條件變好；今天很恐慌，違反計畫的機率確實升高。焦慮與亢奮取最大值而非相加（兩者是互斥狀態），且亢奮的判定門檻（60）刻意高於焦慮（40）：對投資有信心本身是正常狀態。

### 3. 行為偏誤不加進風險分數

偏誤只做上限 10 分的折價，主要輸出是**護欄處方**（`src/data/guardrails.json`）。行為構面的產品意義是「怎麼幫他守住計畫」，不是「他該不該冒險」。處分效應屬執行面偏誤，只驅動護欄，不進 `bias_index`。

### 4. 快變數與慢變數分離

Stage 1（財務）與 Stage 3（偏好、知識經驗）是絕對量表的慢變數；Stage 2 是累加後正規化的行為快變數。Stage 2 的任何題目都不得貢獻 capacity 或 willingness（有測試保證），因此恐慌版與平靜版的 baseline 完全相同，只有情緒層在動。

行為維度的理論值域由程式掃描題庫自動推導，不硬編：改任何 delta 都不會與值域不同步，也避免量表長度不同造成的隱含權重。

### 5. 同構念多框架

willingness 由兩題組成：Q15（單邊損失框架）與 Q15b（雙邊區間框架，下緣與 Q15 對齊、上緣對數對稱）。個人兩題相差兩級以上時記 `framing_sensitivity`；兩題在樣本層級的相關係數則作為 willingness 測量信度的檢驗。

### 6. Q12 雙路徑

自評排名同時餵 `confidence`（線性，當下自信水準 → 情緒層）與 `overconfidence`（需搭配高交易頻率，自信與行為的落差 → 偏誤層）。兩者測的是不同性質，並非重複計分。高自信＋高交易頻率＋高紀律視為專業交易者樣態，豁免交易冷靜期護欄，但情緒折價照算。

### 7. MBTI 只決定措辭

MBTI 僅用於調整結果頁的說明方式，不進任何計分、比對或護欄。型別系統強制這件事：`compose()` 的輸入把 `presentation_layer` / `mbti` / `tone` 宣告為 `never`，並有測試掃描計分模組不得引用任何人格資料。

措辭分成兩層：

| 層 | 資料 | 數量 | 內容 |
| --- | --- | --- | --- |
| **開場白** | `src/data/mbti_voices.json` | 16（每個型別一句） | 人格語氣。只描述「這份結果是什麼、會怎麼說」 |
| **事實段** | `src/data/tone_templates.json` | 5（分析／外交／守衛／探險／中性） | 分數、矛盾、瓶頸、護欄。填的是同一組欄位 |

開場白是唯一一個 MBTI 可能在型別檢查毫無察覺的情況下變成「建議」的地方。一句寫給 ESTP 的「開滿槓桿」，會直接印在有效風險分數 18 分、護欄強制 48 小時交易冷卻的正上方——同一頁自打嘴巴，而且往有害的方向打。

所以開場白**只能描述，不能指示**。`tests/voice.test.ts` 逐句掃黑名單（槓桿、停損、重倉、建倉、加碼、進場、出場、當沖、期權、定存、ETF、債券、飆股、建議、應該……），16 句全部要過，且不得出現任何數字——沒有數字，就不可能和上面的分數矛盾。

事實段不受影響，有測試證明：五組模板必須使用完全相同的資料欄位，渲染後都包含相同的分數、長期承受度、類型與護欄數量；十六個型別跑同一份作答，`scoring_layer` 逐位元組相同。

### 8. 文字情緒只做對照

老師框架的 Sentiment Analysis 會對開放式回答產生焦慮、損失趨避、自信的解讀，但只在結果頁與選擇題結果並排顯示，不進計分：文字中的情緒訊號極易被假設語氣（「如果崩盤我會很恐慌」）污染，而這些構面用情境選擇題已能量測。文字層只修正它真正勝過選項的兩個指標（過度自信、從眾）。

### 8.5 規格的「範例題」是題型，不是題目

規格圖裡第二階段列了三個範例問題，並標明「範例」。要分清楚哪些必須照做、哪些不該照抄：

**必須照做的是輸出。** 五個行為／情緒指標（焦慮、損失規避、自信程度、從眾傾向、過度自信）是規格要求的結果，不是建議，照做才算完成。

**不該照抄的是題目本身。** 最初三題確實貼著範例走，其中兩題近乎逐字：

| 規格範例 | 原本的題目 |
|---|---|
| 最近市場波動很大，您目前對自己的投資有什麼感受？ | Q09「最近市場波動大，你對自己的投資感受是：」 |
| 如果您的朋友靠 AI 股票賺了 30%，而您的投資只有 5%，您會怎麼做？ | Q10「朋友買股票賺了 30%，你只賺 5%，你會：」 |

而且轉換本身有個矛盾：範例三題都是**開放式、都問「為什麼」**，改成選擇題之後「為什麼」不見了，卻還留著範例的措辭——等於拿走了範例的優點，留下它的外型。

改寫後（deltas 完全沒動，測的是同一組構念）：

- **Q09** 從自陳感受換成行為錨定：「最近一個月，你查看投資帳戶的頻率、以及看完當下的心情，比較接近：」。人會低估自己的焦慮，但說得出自己一天看幾次。選項[0]和[3]刻意都是「一天看好幾次」——**同樣的行為，不同的情緒**，頻率本身分不出焦慮和亢奮。
- **Q10** 換一個社會比較的場景：「同事在群組貼出他這季的獲利截圖，數字比你高不少。」

Q08 原本就已經改寫得夠遠（具體金額、App、三則新聞的資訊環境），保留不動。

「為什麼」沒有消失，它被集中到 Q13／Q14 兩題開放式，交給文字分析處理——那才是需要理由的地方，也是唯一能真正讀懂理由的地方。

### 9. 不評斷多空，只分析論證結構

本系統不評斷受訪者的多空立場，只分析其論證結構。過度自信的操作型定義是「語氣強度與論據強度的落差」：`overconfidence = 立場強度 × (100 − 論據深度) / 100`，與看多看空無關——「比特幣絕對是詐騙」與「比特幣絕對會漲」拿到相同的立場強度。

數字分兩種：出現在機制詞（本益比、營收、利率…）附近的數字才算論據；出現在漲、跌、倍、萬鎂附近的是價格型數字，不算論據。否則「絕對會漲到 50 萬鎂，朋友去年翻三倍」會和嚴謹論述拿到一樣的論據分數。

### 10. 文字是加分資料，不是必要條件

開放式回答不設字數門檻，只在少於 30 字時顯示淡色提示。強制字數只會把「不想寫」變成「亂打湊字數」。系統對每段回答判斷品質：`invalid`（空白、亂打、照抄題目）不送分析、文字權重 0；`thin` 權重降為 0.15；`usable` 為 0.3。任何品質都不影響使用者拿到完整結果。

主要分析器失敗（429、逾時、斷網）時，無聲降級到規則式分析器。規則式分析器刻意只做詞表比對、否定詞視窗與線性映射（約 140 行、不裝斷詞套件），它的任務是讓流程不中斷，不是準確；假設語氣與程度副詞交給 LLM。

### 10.1 文字要動到分數，必須先通過兩道閘門

這一節是被一次真實申訴逼出來的。受訪者寫「大盤長期向上 所以投資股票 大盤可以」，結果頁的過度自信顯示「選擇題 低／文字 中」，他的反駁是「但大盤確實長期向上啊」。查下去發現兩個分析器**各壞一種，而且不是同一種壞法**：

| | 分數 | 引用證據 |
|---|---|---|
| 規則式 | 40（中） | `[]` |
| Gemini | 80（高） | `["大盤長期向上 所以投資股票 大盤可以"]` |

規則式的 `stance` 基準值是 40，而 `tiers.mid_min` 是 36——**「偵測不到任何訊號」與「中度過度自信」是同一個輸出**。「我不知道」「今天天氣很好」同樣拿到 40（中）。

Gemini 那 80 分則不是幻覺，它引用的是真的原文。問題出在構念本身：`overconfidence = 立場強度 × (100 − 論據深度)`，而 18 個字的答案裡**論據深度必然是 0**——不是因為這人沒有理由，是因為這麼短的句子放不下理由。短答案在數學上被強制推高過度自信。

因此文字層要動到分數，必須同時通過兩道閘門（`textApplies()`，`src/lib/scoring/behavior.ts`）：

1. **舉不出原文，就不准改分數。** 分析器引用不出受訪者句子的判定，不參與混合。這同時關掉了另一個洞：模型捏造的引用會被逐字比對丟棄（§11），證據欄因此變空，分數也就跟著被撤銷——**編造證據的模型，它的分數本來就不該被採用**。
2. **過度自信另外要求字數。** 低於 `thresholds.depth_floor_chars`（40 字，兩題合計）不採計，因為論據深度在那個長度下量不出來。從眾不受此限：「大家都在買」是有就是有，跟長度無關。

被擋下的指標不是記 0 或記 50，而是**完全交還給選擇題**——選擇題本來就獨立涵蓋全部行為指標。結果頁會直接寫出「未採計」與原因，而不是照樣印一個「中」。

代價寫在這裡：規則式現在也更難把過度自信**往下**壓——它只在引用得出保留詞或機制詞時才有機會。為此規則式的證據欄改為涵蓋所有真正驅動分數的詞（肯定詞、保留詞、機制詞、社會歸因詞、獨立判斷詞），而不是只有肯定詞。

一致率表（§16）不受影響：那張表量的是分析器自己的判定，混合閘門在其下游。改動前後 15 組標註案例的四個欄位一格都沒變。

### 11. 資料最小化

Stage 1、3 的財務數字永遠不離開瀏覽器；只有 Q13、Q14 的開放式文字會送到 `/api/analyze`，且送出前先剝除金額、年齡、email、電話、身分證字號與任職資訊，伺服器端再剝一次。

**上市公司名稱、股票代號與產業名詞不剝除**——「輝達」「台積電」正是被分析的內容，剝掉等於毀掉答案。

Gemini free tier 的條款允許 Google 將輸入用於模型訓練，因此資料最小化是必要設計，不是裝飾。API key 只存在於環境變數，且以 `x-goog-api-key` 標頭傳送，不會出現在網址中。

模型回傳的引用會逐字比對原文，對不上的一律丟棄——引用必須是受訪者真的寫過的句子。

### 12. 降級是常態，不是例外

Gemini free tier 有速率限制，429 是常態：多人同時填答、或展示前連按幾次就會撞到。任何失敗（429、逾時、斷網、金鑰未設定）都會無聲降級到規則式分析器，使用者看不到錯誤，流程不中斷。已實測：指定 `VITE_ANALYZER=gemini` 但 API 不存在時，結果頁顯示「規則式分析（離線備援）」，畫面上沒有任何錯誤。

`/api/analyze` 的 rate limit 為每 IP 每分鐘 5 次，但採單 instance 記憶體計數，在 serverless 環境下非嚴格保證（各 instance 各自計算）。正式環境應改用集中式計數（如 Upstash Redis）。知道自己的防護有多強，比假裝它很強有價值。

### 13. 動態的證明：雙情境對照

以下數字由 `npm run demo` 直接從引擎輸出，README 不手寫任何一個。同一位受訪者、同一份 Stage 1 與 Stage 3 答案，只換掉 Q08、Q09 與兩段開放式文字：

| | 平靜版 | 恐慌版 | |
|---|---:|---:|---|
| capacity | 78.5 | 78.5 | 不變 |
| willingness | 65.5 | 65.5 | 不變 |
| competence_cap | 100.0 | 100.0 | 不變 |
| **baseline_risk** | **65.5** | **65.5** | **不變** |
| emotional_deviation | 0.0 | 100.0 | 變動 |
| bias_index | 17.2 | 47.9 | 變動 |
| emotion_mult | 1.000 | 0.850 | 變動 |
| effective_risk | 65.5 | 55.7 | 變動 |
| target_vol | 13.5% | 12.2% | 變動 |
| Behavioral Alert | 無 | 觸發 | 變動 |
| 投資人分類 | Growth | Balanced | 變動 |

（`bias_penalty` 這兩組皆為 0，原因見 13.2。）

重點不是右欄變小，而是**上半部完全沒有動**。一個人不會因為今天恐慌就變窮、或突然不想承擔風險；變的是他這一刻更可能在低點賣掉。慢變數與快變數分屬不同層，這張表是可驗證的證明——`tests/demo.test.ts` 會在每次 `npm test` 重新檢查這四項是否真的相等，`npm run demo` 在不相等時以非零狀態碼結束。

### 13.1 四組展示情境與它們各自證明的事

| 情境 | baseline | 受限於 | bias_penalty | effective | 用來展示 |
|---|---:|---|---:|---:|---|
| 平靜版 | 65.5 | willingness | 0.00 | 65.5 | 基本盤 |
| 恐慌版 | 65.5 | willingness | 0.00 | 55.7 | 慢變數不動、情緒層在動 |
| 矛盾案例 | 19.5 | willingness | 0.00 | 19.1 | min() 不取平均；capacity − willingness = 79 |
| 高自信從眾 | 55.0 | **competence** | **2.59** | 44.2 | 偏誤扣分、Q12 交互項高分角落、competence 成為 binding |

第四組是後加的，理由要說清楚：前三組**沒有任何一組觸發 `bias_penalty`、走到 Q12 交互項的 +30 角落、或讓 competence 成為 binding constraint**。三條計分路徑從未被展示過，格子圖等於在展示一個沒人走過的分支。`tests/demo.test.ts` 直接把「只有這一組會踩到這三條路徑」寫成斷言——它若不再覆蓋這些路徑，就沒有存在理由。

這一組不是把恐慌版改到數字好看（那是造資料），是另一種人：自評贏過 90% 散戶、每月交易超過 15 次、以他人動向為理由，同時極不願意實現虧損。最後一項不是矛盾，而是處分效應的典型組合——對自己的判斷有信心，但不肯認賠出場。

### 13.2 bias_penalty 為什麼多數情況是 0

`bias_index` 是焦慮、損失趨避、過度自信、從眾四項的**平均**，扣分為 `clamp(0.2 × (bias_index − 50), 0, 10)`。

窮舉題庫可得：`bias_index` 的理論可達範圍是 **0 ~ 90.9**，對應扣分 0 ~ 8.18，上限 10 從來碰不到。但要逼近 90.9，受訪者必須同時在 Q09 選「睡不太好」和「很興奮」——那是互斥的，也就是說**只有內部不一致的作答才能把四項同時拉滿**。一個說得通的高偏誤者（本專案第四組）落在 63.0，扣 2.59 分。

這是刻意的設計結果，不是 bug：行為偏誤的主要輸出是**護欄**（第四組觸發 7 條），不是把風險分數扣掉。扣分只做一件事——在偏誤明顯偏高時，讓建議再保守一點點。若把扣分權重調大，等於用行為問卷去覆蓋財務問卷的結論，那是另一套主張，本專案不採用。

### 14. 可解釋性是法規要求，不是加分項

結果頁的「稽核面板」可以把任何一個分數展開，看到：來自哪幾題、各貢獻幾分、權重多少、走了哪條規則、文字分析引用了哪一句原文。

這不是為了炫技。MiFID II 的適合度報告要求說明「為何這項建議適合這位客戶」，金管會對自動化投資顧問的規範也要求業者能解釋演算法的判斷依據。一個說不出理由的分數，在金融場域不能用。

實作上有一個刻意的限制：`explain()` 不自己算任何數字，它重用 `compose()` 用的同一批純函式，而 `tests/audit.test.ts` 會逐項對帳（各構念的貢獻加總 = 構念分數、各維度的加分加總 = 原始值、算式重述 = 引擎輸出）。稽核面板若與報告說的不一樣，測試會先失敗。Q12 的交互項用完整 4×4 格子呈現，因為它是全系統唯一的非線性規則——橫著看會發現只提高交易頻率幾乎不加分，直著看會發現只提高自評也不加分，只有右下角才是 30。長條圖畫不出這件事。

### 15. 展示不依賴別人的服務

`src/data/demo_fixtures.json` 存四組預錄的完整作答（平靜版、恐慌版、矛盾案例、高自信從眾案例），從首頁一鍵載入。展示模式一律走規則式分析器，不連網：教室 Wi-Fi 會擋外連、free tier 會 429，展示不能死在別人的服務上。雙情境那兩組本來就必須預錄，因為它要求輸出完全可重現，而 LLM 即使 `temperature = 0` 也不保證每次相同。

fixtures 只存「受訪者選了第幾個選項」與原始文字，作答品質、分數、對照表全部在載入時重新推導，因此 fixture 不可能與引擎說不同的故事。

### 16. 規則式與 LLM 的一致率

15 段標註文本（`tests/fixtures.json`），四個欄位，判準見 `docs/codebook.md`。

```
                 規則式        Gemini
overconfidence    86% (12/14)   80% (12/15)
herding           86% (12/14)   87% (13/15)
belief_rigidity   79% (11/14)   80% (12/15)
reasoning_mode    57% (8/14)    93% (14/15)
```

模型 `gemini-3.1-flash-lite`、temperature 0。F12 標記為 `llm_only`（假設語氣＋程度副詞），規則式測試自動跳過，因此規則式分母為 14，Gemini 為 15。

`npm run agreement -- --consistency`（同一段文字連跑 5 次）在 overconfidence、herding、belief_rigidity 三項的標準差皆為 **0.0**。這說明 temperature 0 下對這段文字是可重複的，不等於對所有輸入都可重複——只測了一組。

#### 這張表怎麼讀

**這是一致率（agreement），不是準確率（accuracy）。** 這四個構念沒有客觀存在的正確值，它們由 `docs/codebook.md` 定義；標註者是系統設計者，不是模型。引擎與標註不一致，代表引擎與手冊不一致，不代表標註錯誤。

程序：先寫手冊 → 在未見引擎輸出的情況下標註 → `git commit` 凍結 → 才跑比較。標註凍結後不得為了遷就引擎而個別修改；若要修訂手冊，必須重標全部 15 組並揭露。

**已知限制**：單一標註者，且樣本數小（每組 1 題約佔 7%）。這張表用來說明方法的**相對強弱**，不是精確估計。若要強化，標準做法是加入第二位獨立標註者並計算 Cohen's κ——κ 偏低代表手冊寫得不夠清楚，那本身是值得報告的發現。

#### 目前已經能說的

`reasoning_mode` 只有 57%，其餘三項 79–86%。這個落差不是隨機的：

- **過度自信、從眾**：詞彙訊號明確（「絕對」「一定」「大家都在買」），正則式抓得到
- **信念僵固**：需要對照 Q13 讀 Q14，但仍有結構線索可循
- **推理模式**：要判斷「哪一類理由是主導的」——混合型陳述（有基本面也有他人說法）必須做語意權衡，正則式沒有這個能力

#### 結果：預測成立

這個落差正是 Gemini 欄補上後出現的形狀：

| 指標 | 規則式 | Gemini | 差 |
| --- | --- | --- | --- |
| reasoning_mode | 57% | **93%** | **+36** |
| herding | 86% | 87% | +1 |
| belief_rigidity | 79% | 80% | +1 |
| overconfidence | 86% | **80%** | **−6** |

三項詞彙訊號明確的指標，LLM 沒有帶來實質改善，overconfidence 甚至略低於正則式。唯一大幅拉開的是 reasoning_mode——那正是需要語意權衡、正則式結構上做不到的那一項。

所以文字層只混入 overconfidence 與 herding、且權重不高，而 reasoning_mode 完全交給 LLM，是有量測支撐的，不是憑感覺配 0.3。反過來說，這張表也不支持「把更多指標交給 LLM」：多花的每一次 API 呼叫，在其餘三項上換到的是 +1、+1、−6。

（差距 1 個百分點等於 15 組裡的 0.15 組，也就是同一組都沒差滿。真正可報告的只有 reasoning_mode 那 +36。）

#### 一個部署上的坑

免費層的額度是**按模型、按日**計算的，而不是整個帳號共用一個池。`gemini-3.6-flash` 每天只有 20 次——光是跑一次這張 15 組的表就用掉四分之三，之後所有受訪者都會靜默降級成規則式，而且畫面上完全看不出來（見 §12）。

改用 `gemini-3.1-flash-lite` 是為了額度，不是為了品質：它在這張表上表現與 3.6-flash 相當，證據引用反而更完整。

第一次跑這張表時 15 組有 13 組死在 429／503，只有 2 組回來，表上顯示「100% (2/2)」。那個數字毫無意義：活下來的不是隨機樣本，是剛好沒被限速擋掉的那幾組。`scripts/agreement.ts` 現在會在覆蓋率低於八成時直接標記該欄不可引用。

### 17. 敏感度分析：delta 數值的唯一正當化方式

題庫裡所有 delta 都是**序數專家判斷，不是實證估計**。假裝它們有實證基礎站不住腳；能站得住的是證明結果對它們不敏感。

`npm run sensitivity`，±20% 擾動，隨機種子固定（報告可重現）。受測者為 10 組合成受測者，落在各級距中點 ±5 分內（每級距 2 組）；另有 2 組刻意貼在切點 ±2 分內，**單獨報告、不計入主翻轉率**——貼邊界的樣本任何擾動都會跨界，併進去只會灌高數字。

#### (a)(b) 各 1000 次

| 組 | 門檻 | 分類翻轉率 | Δeffective | Δtarget_vol | 護欄變動 |
|---|---|---:|---:|---:|---:|
| (a) delta 數值 | < 10% | **0.0%** | 0.05 分 | 0.01% | 8.0% |
| (b) 選項值與構念權重 | < 20% | **3.2%** | 2.63 分 | 0.34% | 0.0% |

#### (c) 結構常數，逐一擾動，每個 300 次

| 常數 | 分類翻轉率 | 實際影響到什麼 |
|---|---:|---|
| `investor_types.edges` | **10.5%** | 唯一真正會改變分類的常數 |
| `competence_cap.floor` | 2.1% | 分數移動 0.74 分 |
| `competence_cap.slope` | 0.0% | 分數移動 0.45 分 |
| `emotion.*`（三項） | 0.0% | 分數移動 0.03–0.05 分 |
| `bias_penalty.center` | 0.0% | 分數移動 0.03 分 |
| `tiers.high_min` | 0.0% | **只影響護欄**（變動 10.6%） |
| `target_vol.min` / `.span` | 0.0% | **只影響 target_vol**（0.53% / 0.64%） |
| `bias_penalty.k` / `.max` / `text_blend.usable` / `tiers.mid_min` | 0.0% | 對本樣本完全無作用 |

#### 為什麼不只報翻轉率

翻轉率 0% 可以代表四件完全不同的事：分數動了但沒跨界、只影響 `target_vol`、只影響護欄、或根本沒作用。只報翻轉率會把最後一種寫成「穩健」，那是誤導。因此每一列都同時報分數位移、`target_vol` 位移與護欄變動率，判定欄明講影響落在哪裡。

反過來也有：`investor_types.edges` 的 Δeffective 是 0，卻有 10.5% 翻轉率——它不動分數，它動的是尺規本身。

#### 三個值得寫進報告的發現

**一、delta 幾乎不影響分類，但會影響護欄（0.0% vs 8.0%）。** 這不是巧合，是架構決定的：delta 只透過 `emotion_mult`（下限 0.85）與 `bias_penalty`（上限 10）進入 `effective_risk`，兩者都有界；但它們直接決定各維度的 tier，而 tier 決定護欄。**行為層的主要輸出本來就是護欄，不是風險分數**——敏感度分析量到的正是這件事。

**二、分類的敏感度幾乎全部集中在級距切點。** 唯一超過 10% 的是 `investor_types.edges`。這代表要吵的不是「+30 該不該是 +25」，而是「60 分該不該是成長型的起點」。這是一個可以公開討論、也該公開討論的設計選擇，不是隱藏在權重裡的黑箱。

**三、`bias_penalty.k`、`.max`、`text_blend.usable` 對本樣本完全無作用。** 原因見 §13.2：這 10 組的 `bias_index` 都在 50 以下，扣分被 clamp 在 0，因此扣分的斜率與上限怎麼動都不影響結果；文字權重也只能透過過度自信／從眾 → `bias_index` → 扣分這條路徑進入分數，同樣被擋住。這是誠實的限制陳述：**本次抽樣沒有涵蓋高偏誤受測者**，若要驗證這幾個常數，需要額外抽樣高 `bias_index` 的組別。

#### 可以寫進報告的結論

> 本系統的 delta 值為序數專家判斷，非實證估計。敏感度分析顯示在 ±20% 擾動下，投資人分類的翻轉率為 0.0%（delta）與 3.2%（選項值與權重），顯示分類主要由回答的相對順序決定，而非特定參數值。分類的敏感度集中於級距切點本身（10.5%），而非計分參數。delta 的實際影響落在行為護欄（8.0% 變動），這與「行為層的輸出是護欄而非風險分數」的設計一致。

### 18. 社交層：不計分，就不要做出計分的樣子

12 個興趣選項 + 3 種互動意願，放在**結果頁之後**。問卷中途問興趣會讓脈絡斷掉、跳出率升高；結果看完之後才是順理成章的邀請。

三個刻意的限制：

- **複選、不排序、不加權。** `src/data/interests.json` 裡每個選項只有 `id` 和 `label`，沒有分數欄位——測試會檢查這件事。它真的不計分，就不該長得像會計分。
- **計分模組讀不到它。** `tests/item-bank.test.ts` 掃描 `src/lib/scoring/` 全部檔案，出現 `interest`、`social_layer`、`consent_` 就失敗。與 MBTI 用的是同一道防線。
- **展示情境不會進資料庫。** demo 是示意，不是受訪者。

### 19. 資料收集：同意做在動作裡，不做成勾選框

規格的資料表 schema 收 `responses`（逐題原始作答），裡面就有 Stage 1 的財務答案。所以「要不要上傳」必須是一個明確的決定，而不是預設值。

但**兩個勾選框是錯的介面**。它們把一個決定拆成兩次點擊，然後多數人兩個都不看就勾——同意變成阻力，不是選擇。

現在的做法：結果頁最後有「送出」與「不用，謝謝」兩顆按鈕。**按下送出本身就是同意**，按鈕上方一行小字說會送出什麼、不會送出什麼。沒按，`saveProfile()` 在發出任何請求之前就回傳 `no_consent`。

`consent_research` 與 `consent_matching` 兩個旗標仍然留在 `SocialLayer` 型別與寫入閘門裡，只是不再由 UI 分開詢問；`tests/social.test.ts` 測的是閘門函式，不是介面，所以這兩條路徑仍然逐條被驗證：

1. `consent_research` — 沒有它，`saveProfile()` 在發出請求前回傳 `no_consent`。
2. `consent_matching` — 沒有它，興趣**不是存成空陣列而已，是根本不放進送出的資料**（測試會檢查送出的 JSON 裡不含任何興趣 id）。

其餘防護：

- 匿名。不收姓名、email、IP；主鍵是隨機 uuid。
- 開放式文字在離開瀏覽器前做 PII 剝離，與送給分析器的是同一套規則。
- **非阻斷**。寫入失敗只記 console，結果頁照常顯示。使用者已經拿到他要的東西，不欠我們資料。
- RLS 只開 INSERT。`anon key` 會出現在前端（它本來就設計成公開），所以資料表必須假設任何人都拿得到它：能寫、不能讀、不能改、不能刪。分析時用 service role key 從後台讀，那把 key 絕不進前端。

沒設定 `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY` 時，功能自動關閉，畫面顯示「已記錄在本機（目前未設定資料庫）」，不報錯。

### 20. 沒有「短線／波段型」，這是立場不是遺漏

五種投資人類型（保守／穩健保守／穩健／成長／積極）切的是同一條 0–100 有效風險分數軸，講的是**能承受多少風險**。「做波段」講的是另外兩件事：短持有期 + 高換手率。

一個典型的短線交易者填完這份問卷，會被系統往下壓兩次：

- Q01「這筆錢多久後動用」選「未滿 1 年」→ `horizon = 0` → `capacity` 被壓低
- Q12b「每月交易超過 15 次」→ `overconfidence` 升高 → 觸發 `trade_cooldown_48h`

也就是說，他會拿到一個保守型的分數，和一張叫他冷卻交易的護欄清單。

**這是刻意的。** 理財機器人的目標客群是長期投資人，而短線高換手在風險調整後的預期報酬為負（Barber & Odean, 2000）是這個系統願意站的立場。曾評估過另加一條獨立的「投資風格」軸（長期持有／定期定額／波段／短線），決定不做：多一個標籤會讓系統看起來對兩種做法都認可，而它並不認可。

代價寫在這裡，不藏著：短線使用者會覺得這個工具不懂他。那是設計選擇的後果，不是 bug。

### 21. 能力構念拆成三項，因為兩項的格子太粗

模擬 4000 份前後一致的作答時，五個投資人類型裡**積極型的比例是 0.0%**。追下去發現卡住的不是 `min()` 規則本身，是能力構念的離散度。

舊版 `competence = (知識 + 經驗) / 2`，而兩個來源都很粗：知識測驗兩題給 0/50/100，經驗題給 0/30/50/100。整個能力構念只有 12 種組合、8 個相異值。

`competence_cap = 55 + 0.45 × competence`，要進積極型（80）需要 `competence ≥ 55.6`。把 12 種組合攤開，會看到一道牆：

| 知識 | 經驗 | competence | 上限 | |
|---|---|---|---|---|
| 100（兩題全對） | 30 | 65 | 84.3 | 過 |
| 50（對一題） | 100（抱到結束） | 75 | 88.8 | 過 |
| **50（對一題）** | **50（停損出場）** | **50** | **77.5** | **差 2.5 分** |
| 0 | 100 | 50 | 77.5 | 差 2.5 分 |

答對一題、崩盤時停損出場的人，天花板剛好是 77.5——**無論多有錢、期限多長、多敢冒險，都進不了積極型**。那個 2.5 分的距離不是任何道理決定的，是格子的位置決定的。

改法是把格子做密，不是改參數：

- **知識測驗 2 題 → 4 題**（0/25/50/75/100）。新增「跌 50% 要漲多少才回本」與「分散投資降低哪一種風險」，兩題都是標準金融素養題。
- **經驗拆成兩個 facet**：`experience`（有沒有抱過一次 20% 回檔）與 `tenure`（實際持有多久）。撐過一次大跌和投資很多年是兩件事，原本被擠在同一個分數裡。
- 權重 `knowledge 0.4 / experience 0.35 / tenure 0.25`。測驗最客觀所以最重；年資不等於實力所以最輕。

結果：`competence_cap` 的相異值從 8 個變成 84 個，離 80 最近的一格從 77.5 變成 **79.8**（差距 2.5 → 0.2），積極型從 0.0% 變成 1.1%。

**沒有改的東西**：`competence_cap` 的斜率 0.45 原封不動。把斜率調成 0.5 可以讓 competence 50 剛好對到 80，但那是為了讓某個數字好看而回頭改公式——先有結論再有公式，正好是這份作業一直在避免的事。

積極型依然罕見（1.1%），這是對的。`min(承受力, 意願, 能力)` 加上情緒只能下調，本來就會讓最高一級很難拿到。差別在於它現在**拿得到**，而不是被格子擋在門外。

> 附帶說明：facet 名稱不能重複。`facetValues()` 用 `out[item.facet] = value` 寫入，兩題共用同一個 facet 名字會無聲覆蓋掉前一題，所以 `tenure` 是新的 facet，不是掛在 `experience` 底下。

### 22. 把整台機器當成母體看，才看得到的三個錯

前面每一條規則都是用單一受測者驗的。改成模擬 6000 份**前後一致**的作答（`npm run distribution`），三個單看個案看不出來的問題立刻現形。

**一、焦慮被扣兩次。** `anxiety` 同時出現在 `emotion_mult`（乘法折扣）和 `BIAS_DIMS`（`bias_index` 四個成分之一）。同一個答案扣兩次：

```
其他偏誤本來就偏高的人，只改焦慮題：
最低焦慮  anxiety=0    mult=1.000  biasIndex=38.5  penalty=0.0  eff=27.0
最高焦慮  anxiety=100  mult=0.850  biasIndex=71.0  penalty=4.2  eff=18.7
                              經由 mult −4.1      經由 penalty −4.2
```

baseline 27 分被單一維度吃掉 8.3 分。規則 2 說「情緒只能下調」、規則 3 說「行為偏誤不加進風險分數」，但焦慮兩條路都走，這個重疊沒寫在任何地方。**焦慮是狀態不是偏誤**，已從 `BIAS_DIMS` 移除，只留在情緒路徑。`bias_index` 現在是 loss_aversion／overconfidence／herding 三項。

**二、畫面寫「情緒平穩」，分數已經在打折。** `state` 在 deviation < 25 時標成 `calm`，但 `emotion_mult = 1 − 0.15 × deviation/100` 只要 deviation > 0 就開始扣。約 30% 的人看到「情緒平穩」的同時被無聲扣分。幅度最多 3.6%，但一個以可解釋性為賣點的系統不能有這種東西。

改成分段：低於 `deviated_min` 完全不打折，超過之後折扣從 0 線性升到 `max_discount`。仍然連續，deviation 24 和 26 不會拿到差很多的組合。稽核面板印的公式也跟著改——面板把公式當字串印，改了引擎沒改面板，面板就會說謊；`tests/audit.test.ts` 正是為此存在，它當場就紅了。

**三、能力構念太粗**，見 §21。

### 23. 五個類型不平均，而這不需要修

> **先修測量工具，再下結論。** §21、§22 最早那幾版數字是用一個有兩個缺陷的模擬量出來的，兩個缺陷都會把分布往下壓：
>
> 1. **θ 假設成均勻分布**——等於假設「極端保守的人」跟「中間的人」一樣多。真人是中間最多。結果是類型分布呈現不該出現的雙峰（兩邊高、中間凹）。
> 2. **一個 θ 同時決定所有題目**——但 Q08／Q09 的最後一個選項是「再投入一些」「很興奮，覺得機會很多」，加的是 `confidence` 與 `overconfidence`。單一 θ 把「敢冒險」和「亢奮又過度自信」綁死，於是模擬出來的高風險受測者會被情緒折扣和偏誤懲罰打回來。**這等於在模擬裡否定了規則 4（快慢變數分離）**，而那正是這套系統的設計前提。
>
> 修正後：θ 改常態、慢變數（承受力／意願／能力）與快變數（情緒／偏誤）各自獨立抽樣。三組數字的對照：
>
> | 模擬 | 保守 | 穩健保守 | 穩健 | 成長 | 積極 |
> |---|---|---|---|---|---|
> | θ 均勻 · 單一 θ | 31.4% | 15.8% | 17.9% | 33.6% | 1.3% |
> | θ 常態 · 單一 θ | 20.0% | 22.7% | 27.2% | 28.9% | 1.1% |
> | **θ 常態 · 快慢分離** | **20.4%** | **22.9%** | **26.1%** | **27.0%** | **3.6%** |
>
> §21 那個「0.0% → 1.1%」的對照仍然成立——前後用的是同一個模擬，比較是公平的，而 77.5 那道牆是真的。但**絕對水準**要看最後一列。

修正後的模擬母體，類型分布是 20% / 23% / 26% / 27% / **3.6%**：單峰、中間最多，積極型罕見。

這是 `min(承受力, 意願, 能力)` 加上「情緒只能下調」的必然結果，兩條都是刻意的設計，不該為了讓長條圖好看而回頭改。

真正的問題是「有一個類型幾乎沒人拿到，那為它設計的投資組合豈不是白做？」——答案是**投資組合本來就不該由標籤決定**。`target_vol = 0.05 + effective_risk/100 × 0.13` 是連續的，兩個都叫「成長型」的人如果分數是 61 和 79，拿到的波動目標本來就不一樣（11.0% 對 15.3%）。標籤只是拿來講話的名字。

因此：**級距維持 0/20/40/60/80 不動。** 曾經考慮過把級距改成模擬母體的五等分點（0/10/31/55/66），讓每型各 20%，但那會把「80 分＝承受力達 80%」的絕對標準換成「排在前 20%」的相對標準，而且是拿**虛構的母體**去校準——有真實使用者資料之前，這種校準只是把假設藏進參數裡。

`target_vol` 沒有顯示在結果頁（使用者不需要看到一個小數），但完整保留在 JSON 匯出裡，供下游的投資組合設計使用。

### 24. 分數本身的盤查：七項可驗證的檢查

前面幾節查的都是「分布」。這一節查的是「分數本身」——七項可以被跑出來、不靠信心喊話的檢查。

**A. 三個構念的權重都正好等於 1。** 通過。

**B. 每個行為維度實際由幾題決定。**

| 維度 | 題數 | 最大單題佔比 |
|---|---|---|
| anxiety | 2 | Q09 62% |
| loss_aversion | 4 | Q08 30% |
| overconfidence | 4 | Q12 55% |
| herding | 2 | Q10 53% |
| discipline | 6 | Q10 26% |
| confidence | 3 | Q12 42% |
| disposition | 2 | Q11 50% |

**初次盤查時 `herding` 和 `disposition` 各只有一題**（Q10 佔 100%、Q11 佔 100%）。問題不只是精度：`high_herding` 和 `high_disposition` 兩條護欄各自由**單一題目的單一選項**決定——Q10 選「跟著買」直接讓 herding 正規化到 100，越過 high 門檻，鎖上季度再平衡與單一部位 10% 上限。看錯一題，護欄就開了。

已補上第二題（見 §25），現在任一題的最差答案都不足以單獨觸發護欄，`tests/scoring.test.ts` 有測試釘住這件事。

**C. 選項值是否隨選項順序單調。** 盤到一個真缺陷：Q20 的選項值是 `0 / 30 / 100 / 50`，第三個選項最高、第四個又掉回中間。填答者預期選項是有序的，這種跳動會讓人誤選。已改為 `0 / 30 / 50 / 100`（沒經驗／已離場／停損出場／抱到結束），語意不變，只是把順序排對。

**D. 地板／天花板效應。** herding 34% 壓在地板、disposition 32%、overconfidence 27%、anxiety 21%。這些「地板」多半是真實的回答類別（「不受影響」本來就該是 0），不是計分錯誤，但確實表示這幾個維度在低端分不出人。

**E. 死題檢查。** 第一版只量 `effective_risk`，結論是「22 題都不影響分數」——**那個指標是錯的**。`min()` 之下，沒有綁住分數的構念本來就動不了它；而 AC1 走的是品質旗標、Q11 走的是護欄，兩者都不改分數。改成量「任何一項輸出有沒有變」之後：**沒有死題**，每一題都會改到某些人的某一項輸出。

**F. 每題的影響力（母體 500 人，換選項後 `effective_risk` 的平均變動）。**

| 題目 | 平均影響 | 會影響到的人 |
|---|---|---|
| Q15 風險容忍 | 23.0 | 97% |
| Q15b 可接受區間 | 15.4 | 91% |
| Q21 投資目標 | 12.7 | 86% |
| Q01 投資期限 | 6.7 | 65% |
| …（其餘 < 6.5） | | |

**三題意願問題決定了大半結果**，而意願在 52% 的人身上是那個綁住分數的構念。這是 `min()` 的直接後果，也是合理的——意願本來就是適合度的核心——但「23 分由一題決定」這件事必須講出來。

知識測驗四題只影響 11% 的人，因為能力現在只在 11.4% 的情況下綁住分數。§21 把能力的格子做密了，卻也因此讓它更少成為瓶頸。誠實的說法是：那次修正解決的是「有人被格子卡死」，不是「能力很重要」。

**G. `bias_index` 三個成分的相關係數。** loss_aversion × overconfidence −0.23、loss_aversion × herding −0.03、overconfidence × herding −0.00。互相獨立，沒有把同一件事算三次。

### 25. 選項中性化，與兩個構念各補第二題

**一、行為題的「正確答案」寫在臉上。**

原本的 Q10 選項：

```
[0] 私訊問他買什麼，然後跟著買            ← 沒人想選
[2] 不受影響，我們的目標和風險承受度不同    ← 標準答案
```

Q08 的「什麼都不做，照原計畫」、Q09 的「幾週才看一次，沒什麼感覺」也一樣。受測者看得出哪個答案讓自己顯得成熟，於是 `herding`、`discipline`、`overconfidence` 量到的可能是他想被看成什麼樣的人，而不是他實際會做什麼。這三個構念正好是護欄的觸發條件。

改法有兩層：

- **措辭去價值判斷。** 「私訊問他買什麼，然後跟著買」→「問他買什麼，然後也買了一些」；「不受影響，我們的目標和風險承受度不同」→「沒有特別反應，我們買的東西本來就不一樣」；「幾週才看一次，沒什麼感覺」→「幾週才想到要看一次」。同樣的行為，不帶評價。
- **Q10 改問過去，不問未來。** 題幹從「接下來一週你最可能」改成「過去遇到這種情況，你後來通常是」。回憶自己做過什麼，比想像自己會做什麼難美化。

`deltas` 完全沒動，測的是同一組構念。**Q15–Q18 沒有動**：那四題是量化或二擇一，沒有期許偏誤的空間，其中 Q16／Q17 是 prospect theory 的經典題組，動了就不是那個測驗了。

**二、`herding` 與 `disposition` 各補第二題。**

| | 新題 | 換的角度 |
|---|---|---|
| Q10b | 兩個條件相當的標的，A 很熱門、B 沒人提，你買哪個 | 上一題問「別人賺錢時你怎麼反應」，這題問「人多本身算不算理由」 |
| Q11b | 一筆賺 20%、一筆賠 20%，必須賣掉一筆，你賣哪筆 | 處分效應的經典測法（Shefrin & Statman）。強迫二選一，沒有選項看起來像正確答案 |

Q10b 的「買 B，人少的時候價格通常比較合理」只給 **−5**，不是 −15：**反向操作不等於獨立判斷**，逆著人群走一樣是被人群決定的。真正的獨立是 Q10 的「沒有特別反應，我們買的東西本來就不一樣」（−10）。

值域從此讓單題無法獨占：任一題選最差答案，`herding` 到 60、`disposition` 到 62.5，都在 high 門檻 65 以下；兩題都選最差才會到 100。`tests/scoring.test.ts` 逐題檢查這件事。

**副作用**：`herding` 值域變寬之後，一般作答正規化後的分數變低，`bias_penalty` 跟著變小，積極型從 3.6% 升到 **5.9%**。這不是調參數調出來的，是補題的連帶結果。
